## Instructions for future scans

1. Read `recent.md`, `Job_Application_Profile_details.md`, `job-listing-tracker.md`, and this file before assessing jobs.
2. Start at the newest homepage card and scan backward through pagination until reaching an already recorded listing. If the user asks for a fixed number, scan that number; otherwise scan to the overlap. State the exact range checked.
3. Compare employer, exact post/title, circular or source date, and deadline. Employer alone does not identify a listing. Record changes to the same notice as updates, and cross-check the bank tracker for duplicates.
4. Report every genuinely new listing, even if Nahid is ineligible. Keep ❌ listings in the report and log; use ⚠️ when a condition is unknown. State every strict requirement relevant to his profile (degree/subject, grades, age/cutoff, experience, district, license, skills, typing, documents, etc.).
5. Follow the compact-table, commute, and separate apply-link rules in `recent.md`. Include Dhaka and Narayanganj commute estimates where verifiable; otherwise flag “⚠️ Verify location/commute.” Only put application links after the table for ✅ and ⚠️ listings.
6. Keep expired listings in the log. Update this baseline with scan date and oldest listing reached; do not call a limited scan exhaustive.
